# בוט התמלול tamlil-bot

גרסה באנגלית: [English](README.md)

בוט טלגרם שמתמלל הקלטות. שולחים לו הודעה קולית, קובץ אודיו או וידאו, או קישור שיתוף, והוא מחזיר תמליל מחולק לפי דוברים, עם עדיפות לעברית, באמצעות [Soniox](https://soniox.com).
אם מגדירים מפתח OpenAI, הוא יודע גם לסכם את התמליל.
אתה מריץ עותק משלך בתוכנית Hobby החינמית של Vercel, ומשלם ל-Soniox רק על האודיו שאתה מתמלל.

ככה נראה תמליל בצ'אט (שני דוברים):

> דובר 1:\
> בוא נתחיל מהתקציב.
>
> דובר 2:\
> בסדר, יש לי שלושה סעיפים.
>
> ⏱ 12:30 · 2 דוברים\
> [ 📋 סכם ]

לא רוצה להתקין כלום? ראה [תמליל](#לא-רוצה-להתקין-כלום) בסוף.

## התקנה עם Claude Code

1. הרץ `git clone https://github.com/sagi770/tamlil-bot.git`
2. פתח את Claude Code בתיקייה `tamlil-bot` (בטרמינל: `cd tamlil-bot` ואז `claude`).
3. תגיד: **תבנה לי את האפליקציה**

ה-Claude Code בודק את המחשב, שואל אם אתה רוצה סיכומים ובאיזו שפה הבוט ידבר, ופותח לך את `.env.local` כדי שתדביק בו את המפתחות. את המפתחות אף פעם לא מדביקים בצ'אט. אחר כך הוא מבקש ממך לשלוח `/start` לבוט החדש, מעלה אותו עם `npm run setup`, ובודק את התוצאה עם `npm run doctor`.

החלק שלך: ליצור את הבוט ב-@BotFather, להוציא את המפתחות, לאשר את ההתחברות ל-Vercel בדפדפן, לשלוח `/start`, ולשלוח הודעה קולית לבדיקה.

## התקנה ידנית

אותם שלבים ש-Claude Code עובר.

**1. בדיקת כלים**

```bash
git clone https://github.com/sagi770/tamlil-bot.git
cd tamlil-bot
node --version
npm install
vercel --version
vercel whoami
```

מה לבדוק בפלט:

- הפקודה `node --version` צריכה להציג v22 ומעלה.
- הפקודה `vercel --version` צריכה להציג 64.6.0 ומעלה. אם הפקודה חסרה או שהגרסה ישנה יותר, הרץ `npm i -g vercel@latest`.
- אם `vercel whoami` מודיע שאתה לא מחובר, הרץ `vercel login`.

הפקודה `vercel login` מדפיסה קישור וקוד. פתח את הקישור (במחשב או בטלפון), ודא שהקוד תואם, ואשר.

ב-Windows PowerShell, אם פקודה נכשלת עם "running scripts is disabled on this system", הוסף לה `.cmd` (`npm.cmd install`, `vercel.cmd login`), או הרץ את הפקודות ב-Command Prompt או ב-Git Bash.

**2. הוצאת המפתחות**

- **טוקן לבוט טלגרם:** בטלגרם, פתח את @BotFather, שלח `/newbot`, בחר שם ושם משתמש שמסתיים ב-`bot`, והעתק את הטוקן.
- **מפתח API של Soniox:** הירשם ב-[console.soniox.com](https://console.soniox.com), פתח את *My First Project*, ואז את *API Keys*, וצור מפתח. טען יתרה תחת [Billing](https://console.soniox.com/org/billing/overview/).
- **מפתח API של OpenAI** (רק לסיכומים): צור מפתח ב-[platform.openai.com/api-keys](https://platform.openai.com/api-keys). בחשבון צריכה להיות יתרת API.

**3. מילוי `.env.local`**

```bash
cp .env.example .env.local
```

ב-Command Prompt אין `cp`, ולכן שם הרץ במקום זאת `copy .env.example .env.local`.

פתח את `.env.local` בעורך טקסט והדבק כל ערך מיד אחרי ה-`=`:

- המשתנים `TELEGRAM_BOT_TOKEN=` ו-`SONIOX_API_KEY=` הם חובה.
- לסיכומים: מחק את ה-`# ` בתחילת השורה `OPENAI_API_KEY=` והדבק את המפתח.
- לבוט באנגלית: שנה את השורה `# BOT_LANGUAGE=he` ל-`BOT_LANGUAGE=en`.

את שאר השורות השאר כמו שהן. הפקודה `npm run setup` ממלאת בעצמה את סודות ה-webhook ואת ה-ID שלך בטלגרם.

**4. שליחת `/start` לבוט החדש**

פתח את הבוט בטלגרם (קישור ה-`t.me/...` ש-BotFather נתן לך) ושלח `/start`. הוא עוד לא יענה, וזה בסדר. ה-setup קורא את ההודעה הזו כדי לזהות את ה-ID שלך ולנעול את הבוט אליך. טלגרם שומרת אותה 24 שעות, אז עשה את זה זמן קצר לפני שלב 5.

**5. העלאה**

```bash
npm run setup
```

אפשר להריץ את ה-setup שוב ושוב, והוא אף פעם לא מדפיס מפתח. הוא מדפיס שורה לכל שלב עם ✓, ⚠ או ✗, ולכל בעיה יש שורת `→` עם הצעד הבא. ריצה מוצלחת מלאה כוללת 17 שלבים ומסתיימת כך (בקיצור; הפלט באנגלית):

```text
tamlil-bot setup

✓ Read .env.local
✓ Telegram bot token: @your_bot
✓ Soniox API key: accepted
✓ OpenAI summaries: key and model gpt-6-luna work
✓ Webhook secrets: generated TELEGRAM_WEBHOOK_SECRET and SONIOX_WEBHOOK_SECRET in .env.local
✓ Owner (who may use the bot): locked to @you (Telegram id 123456789), saved as ALLOWED_USER_IDS
…
✓ Ready message: sent to Telegram id 123456789

Summary
  …
  17 ok, 0 warnings, 0 failed

Your bot: https://t.me/your_bot
Access:   locked to one Telegram user: 123456789
```

מה ה-setup עושה, לפי הסדר: בודק את שלושת המפתחות (בדיקת OpenAI היא סיכום אמיתי וקצר אחד), יוצר את שני סודות ה-webhook, נועל את הבוט אליך, בודק את Vercel CLI ואת ההתחברות, מקשר את התיקייה לפרויקט Vercel בשם `tamlil-bot` (ויוצר אותו אם צריך), שומר את המשתנים ב-production של Vercel, מעלה את הבוט (בדרך כלל דקה עד שלוש דקות), רושם את ה-webhook ואת תפריט הפקודות בטלגרם, בודק ששתי נקודות הקצה (של טלגרם ושל Soniox) עונות ודוחות בקשות בלי הסוד, מתמלל את קובץ הדוגמה של Soniox (ממתין עד 3 דקות), וכשהבוט נעול אליך, שולח לך "הבוט מוכן. שלח לי הודעה קולית כדי לנסות."

**6. בדיקה וניסיון**

```bash
npm run doctor
```

כשהכול תקין, הפלט מסתיים ב-`10 ok, 0 warnings, 0 failed`. אחר כך שלח לבוט הודעה קולית.

בדוק ששורת ה-"Owner" של ה-setup מציגה אותך. אם הטוקן של הבוט כבר שימש בעבר, ייתכן שה-setup מצא `/start` ישן של מישהו אחר. במקרה כזה כתוב ב-`.env.local` את השורה `ALLOWED_USER_IDS=<ID>` עם ה-ID שלך, והרץ שוב `npm run setup` (הבוט מציג לך את ה-ID שלך כשהוא מסרב לך).

אם ה-setup לא הצליח לנעול את הבוט אליך, הוא מסמן את שלב ה-"Owner" ב-⚠ והבוט נשאר פתוח לכולם. מה עושים תלוי במה שכתוב בשורה הזו:

- אם כתוב "the bot is already live, so setup cannot read your /start": שלח לבוט `/id`, ואז הרץ `npm run setup -- --owner-id=<ID>` עם ה-ID שלך במקום `<ID>`.
- אם כתוב "no /start message found": שלח לבוט `/start` והרץ שוב `npm run setup`. אם אותה ריצה כבר חיברה את הבוט לטלגרם (✓ בשלב "Telegram webhook"), הריצה הבאה רק תגיד שהבוט כבר מחובר, ולכן במקרה כזה השתמש ב-`/id` כמו בסעיף הקודם.

## שימוש

- **הקלטות:** שלח הודעה קולית, קובץ אודיו, וידאו, הודעת וידאו עגולה, או קובץ אודיו/וידאו שנשלח כמסמך, עד 20MB. הבוט עונה "⏳ מתמלל…" ואחר כך מגיב להקלטה עם התמליל.
- **הפורמט:** כשיש דובר אחד, התמליל הוא טקסט רגיל; כשיש כמה דוברים, כל קטע מתחיל בתווית כמו "דובר 1:" או "דובר 2:". השורה האחרונה מציגה את האורך ואת מספר הדוברים (`⏱ 12:30 · 2 דוברים`). תמליל ארוך מ-3,500 תווים מגיע כקובץ `.txt` עם חותמות זמן, בשם `תמליל YYYY-MM-DD HH-MM.txt`.
- **קבצים גדולים יותר:** שלח קישור שיתוף. קישורי Google Drive ו-Dropbox מומרים להורדה ישירה, וגם קישור `https` ישיר לקובץ אודיו או וידאו מתקבל. השיתוף חייב להיות "כל מי שיש לו את הקישור". Soniox מוריד את הקובץ בעצמו.
- **סיכום** (רק כשמוגדר `OPENAI_API_KEY`): לחץ "📋 סכם" מתחת לתמליל, על הודעה או על קובץ `.txt`. כדי לקבל סיכום אוטומטית, כתוב "סיכום" בכיתוב של ההקלטה, או באותה הודעה עם הקישור (גם "תקציר", "סכם", "תסכם" ו-"summary" עובדים). הסיכום הוא טקסט פשוט בשפת ההקלטה: הנושא, הנקודות העיקריות, והחלטות ומשימות אם היו.
- **פקודות:** הפקודה `/start` לפתיחה, `/help` לעזרה, ו-`/id` כדי לקבל את ה-ID שלך בטלגרם.
- **מי יכול להשתמש:** רק מזהי הטלגרם שב-`ALLOWED_USER_IDS`. כל אחד אחר מקבל "אין לך הרשאה להשתמש בבוט הזה." עם ה-ID שלו, שאותו הוא יכול לשלוח לך. להוספת אנשים ראה [משתני סביבה](#משתני-סביבה).

## משתני סביבה

ההגדרות שלך נמצאות ב-`.env.local`. הפקודה `npm run setup` מעתיקה ל-production של Vercel כל משתנה שיש לו ערך, ומוחקת מ-Vercel את אלה שריקים או חסרים ב-`.env.local`. כדי לשנות הגדרה, ערוך את `.env.local` והרץ שוב `npm run setup`. שינוי שנעשה רק בממשק של Vercel יתבטל ב-setup הבא.

| סוג | משתנה | מה הוא עושה |
|---|---|---|
| חובה | `TELEGRAM_BOT_TOKEN` | הטוקן של הבוט מ-@BotFather. |
| חובה | `SONIOX_API_KEY` | מפתח API מהקונסולה של Soniox. |
| נוצר ב-setup | `TELEGRAM_WEBHOOK_SECRET` | מאמת בקשות מטלגרם. |
| נוצר ב-setup | `SONIOX_WEBHOOK_SECRET` | מאמת בקשות מ-Soniox. |
| מומלץ מאוד (ה-setup ממלא) | `ALLOWED_USER_IDS` | מזהי הטלגרם שמורשים להשתמש בבוט, מופרדים בפסיקים. ריק: הבוט עובד לכולם ומזהיר. ערך ברשימה שאינו מזהה מספרי לא נלקח בחשבון, אבל הבוט נשאר נעול (למזהים התקינים, או לאף אחד), וה-setup וה-doctor נכשלים ומציינים את הערך הזה. |
| לא חובה | `ALLOW_ALL_USERS` | הערך `true` הופך את הבוט לציבורי בכוונה, בלי אזהרה. אם גם `ALLOWED_USER_IDS` מוגדר, הנעילה גוברת. |
| לא חובה | `OPENAI_API_KEY` | מפעיל את הסיכומים. |
| לא חובה | `OPENAI_MODEL` | ברירת מחדל `gpt-6-luna`. מודל אחר צריך לתמוך ב-Chat Completions עם `reasoning_effort`. |
| לא חובה | `BOT_LANGUAGE` | עברית `he` (ברירת מחדל) או אנגלית `en`: השפה של ההודעות ושל תפריט הפקודות. |
| לא חובה | `BOT_TIMEZONE` | אזור זמן IANA לשמות קובצי ה-`.txt`. ברירת מחדל `Asia/Jerusalem` ל-`he`, `UTC` ל-`en`; אם האזור לא תקין, הבוט משתמש בברירת המחדל. |
| לא חובה | `LANGUAGE_HINTS` | רמזי שפה ל-Soniox, מופרדים בפסיק. ברירת מחדל `he,en`. |
| לא חובה | `SONIOX_MODEL` | ברירת מחדל `stt-async-v5`. |
| לא חובה | `SONIOX_CONTEXT` | שמות ומונחים שמשפרים את הדיוק. טקסט חופשי: עטוף אותו במירכאות כפולות, כי ` #` בלי מירכאות מתחיל הערה. |
| לא חובה | `PUBLIC_BASE_URL` | דומיין מותאם (`https://...`) לשני ה-webhooks. אחרת ה-setup רושם בטלגרם את דומיין ה-production של הבוט ב-Vercel, וה-webhook של Soniox נשלח לאותה כתובת שטלגרם פונה אליה. |

דוגמה להוספת אדם נוסף: `ALLOWED_USER_IDS=123456789,987654321`, ואז `npm run setup`.

| פורמטים | מה ש-Soniox מקבל: aac, aiff, amr, asf, flac, mp3, ogg, wav, webm, m4a, mp4. |

נבדק בפועל עד עכשיו: הודעות קוליות, שני דוברים, הקלטות ארוכות כקובץ `.txt`, וידאו, קובץ מעל 20MB (נדחה עם ההנחיה לשלוח קישור), קישורי Google Drive (28MB דרך הבוט, 62MB דרך אותו תהליך בהרצה מקומית), סיכומים בכפתור ובכיתוב, סירוב לזר, ונעילה עם `--owner-id`.

עוד לא נבדק בפועל: קישורי Dropbox, קישורים מאתרים אחרים, קבצים ב-Google Drive מעל 100MB (ייתכן ש-Drive יחזיר דף אזהרה, ואז הבוט עונה שהקישור לא מוביל לקובץ אודיו או וידאו), הודעות וידאו עגולות, הנעילה האוטומטית לפי ה-`/start` ששולחים לפני ה-setup הראשון, ו-`npm run dev`. שתי תצורות, בלי מפתח OpenAI ועם `ALLOW_ALL_USERS=true`, מכוסות בבדיקות יחידה אבל עוד לא נבדקו בפועל.

## פרטיות

- קובץ שנשלח בטלגרם עובר רק דרך הזיכרון של הפונקציה בדרך ל-Soniox. כששולחים קישור, Soniox מוריד את הקובץ בעצמו, והקובץ לא עובר דרך Vercel בכלל.
- אחרי שהתמליל נמסר, התמלול והקובץ שהועלה נמחקים ב-Soniox. אם המסירה נכשלת שוב ושוב, המשימה נשארת ב-Soniox עד המחיקה האוטומטית אחרי 30 יום (`npm run doctor` מדווח על שאריות כאלה).
- מאותו רגע התמליל קיים רק בצ'אט שלך בטלגרם.
- הלוגים מכילים רק שמות אירועים וכמה שדות פשוטים כמו שמות של סוגי שגיאות (`job_started`, `access_denied`, ...): בלי טקסט של תמליל, בלי מזהים או שמות מטלגרם, בלי מפתחות.
- קישור ההורדה של טלגרם מכיל את הטוקן של הבוט, ולכן הוא לא נכתב ללוג ולא נשלח ל-Soniox.
- מלבד האודיו, Soniox מקבל גם את מזהה הצ'אט ואת מזהי ההודעות (בשדה `client_reference_id`, כדי שהתוצאה תחזור לצ'אט הנכון) ואת שם הקובץ המקורי.
- שתי נקודות הקצה דוחות כל בקשה בלי הסוד הנכון (HTTP 401).
- כשהסיכומים פעילים, טקסט התמליל נשלח ל-OpenAI.
- בוט פתוח מאפשר לכל מי שמוצא אותו לתמלל על חשבון היתרה שלך ב-Soniox וב-OpenAI. לכן ה-setup נועל אותו אליך.

## תוכנית Hobby של Vercel: כמה זה מחזיק ותנאי השימוש

תוכנית Hobby כוללת בכל חודש 4 שעות של Active CPU, 360 GB-שעות של זיכרון ומיליון הפעלות של פונקציות ([תוכנית Hobby של Vercel](https://vercel.com/docs/plans/hobby)).

נמדד על הבוט החי: תמלול אחד עם סיכום לוקח בערך 3 הפעלות, עד 0.5 שניות CPU ועד כ-17 שניות של זמן מופע. זה מספיק לאלפי תמלולים בחודש ([המדידות](docs/DECISIONS.md#vercel-hobby-usage--measured-task-16-2026-11-22)). קבצים שנשלחים כקישור לא עוברים דרך Vercel בכלל.

התוכנית חינמית ואין בה מחזור חיוב. אם עוברים מגבלה, ב-Vercel כותבים שברוב המקרים "you will have to wait until 30 days have passed before you can use the feature again", כלומר צריך לחכות עד שיעברו 30 יום כדי להשתמש שוב באותה יכולת.

לפי [תנאי השימוש](https://vercel.com/legal/terms) של Vercel (סעיף 4, Hobby Plan): "You shall only use the Services under a Hobby plan for your personal or non-commercial use", כלומר שימוש אישי או לא מסחרי בלבד. בוט להקלטות שלך מתאים. אם אתה משתמש בו לעסק, בדוק את תנאי השימוש ואת [הנחיות ה-fair use](https://vercel.com/docs/limits/fair-use-guidelines) של Vercel, או שאל אותם.

## פתרון תקלות

מתחילים מכאן:

```bash
npm run doctor
```

הפקודה הזו לא משנה כלום. היא בודקת את `.env.local`, את שלושת המפתחות (כשהסיכומים פעילים, קריאה קצרה אחת ל-OpenAI), את ה-webhook בטלגרם כולל שגיאת המסירה האחרונה, ששתי נקודות הקצה עונות ודוחות בקשות בלי הסוד, את הקישור ל-Vercel, את מצב ההרשאות ואת ההקלטות שנשארו ב-Soniox. לכל ✗ או ⚠ יש שורת `→` עם הצעד הבא.

**הבוט לא עונה**

- זה צפוי אם עוד לא הרצת את `npm run setup`: לפני כן שום דבר לא מחובר.
- אם ה-doctor מסמן את "Telegram webhook" ב-✗, הרץ `npm run setup`. אם הוא מציג את שגיאת המסירה האחרונה של טלגרם, בדוק את הלוגים של הפונקציה בממשק של Vercel (Logs; ב-Hobby הם נשמרים שעה אחת) והרץ שוב `npm run setup`.
- אם שלב ה-"Webhook endpoint check" של ה-setup או של ה-doctor אומר שהדומיין מאחורי Vercel Deployment Protection: טלגרם ו-Soniox לא יכולים לפנות לכתובת מוגנת. בממשק של Vercel פתח את הפרויקט, ואז Settings, ואז Deployment Protection, וכבה אותה ל-production, או קבע את `PUBLIC_BASE_URL` לדומיין ציבורי. אחר כך הרץ `npm run setup`.
- בקבוצה הבוט שותק בכוונה: הוא עובד רק בצ'אט פרטי.

**"יתרת התמלול נגמרה. פנה לבעל הבוט כדי שיטען אותה."**

היתרה שלך ב-Soniox ריקה: טען יתרה ב[קונסולה של Soniox](https://console.soniox.com/org/billing/overview/) (או הפעל שם טעינה אוטומטית), ואז שלח את ההקלטה שוב. Soniox מסרב באותה דרך גם כשמגיעים לתקרת תקציב חודשית שהגדרת בקונסולה שלו, והבוט מציג אותה הודעה: הגדל את התקרה. גם השלב "Soniox test transcription" של ה-setup תופס את זה.

**"לא הצלחתי לסכם. התמליל לא נפגע, ואפשר לנסות שוב עם הכפתור "📋 סכם"."**

הרץ `npm run doctor`. השורה "OpenAI summaries" שלו מבצעת קריאה אמיתית אחת ואומרת מה הסיבה: מפתח שגוי (HTTP 401), אין יתרה (`insufficient_quota`), או מודל שהחשבון שלך לא יכול להשתמש בו (מחק את `OPENAI_MODEL` כדי לחזור לברירת המחדל). כדי לכבות סיכומים, מחק את `OPENAI_API_KEY` מ-`.env.local` והרץ `npm run setup`.

**הכלי Vercel CLI לא מחובר, חסר או ישן**

הרץ `vercel login`, אשר בדפדפן, ואז הרץ שוב את ה-setup:

```bash
vercel login
npm run setup
```

אם `vercel` חסר או ישן מגרסה 64.6.0, הרץ `npm i -g vercel@latest`. ב-Windows PowerShell ראה את ההערה על `npm.cmd` ו-`vercel.cmd` ב[התקנה ידנית](#התקנה-ידנית).

**הבוט פתוח לכולם**

בוט פתוח שולח "⚠️ הבוט הזה פתוח לכולם" עם ה-ID שלך אחרי `/start` ואחרי כל תמליל. כדי לנעול אותו, עשה מה שכתוב באזהרה: הוסף ל-`.env.local` את השורה `ALLOWED_USER_IDS=<ID>` עם ה-ID שלך, והרץ `npm run setup`. אפשר גם לשלוח לבוט `/id`, ואז להריץ את הפקודה הבאה עם ה-ID שלך במקום `<ID>`:

```bash
npm run setup -- --owner-id=<ID>
```

אל תוסיף את המשתנה רק בממשק של Vercel: ה-setup הבא מוחק אותו.

**ה-setup נכשל בשלב "Vercel project"**

קרא את השורות שמתחילות ב-`|` מתחת לשלב: זו ההודעה של Vercel CLI עצמו. אם הן מזכירות בחירה של team או scope, לחשבון שלך יש כמה צוותים. הצג את הצוותים, עבור לצוות שבו הבוט צריך לגור (ה-slug הוא השם שמופיע בכתובת של הצוות, `vercel.com/<slug>`), והרץ שוב את ה-setup:

```bash
vercel teams ls
vercel switch <team-slug>
npm run setup
```

הפקודה `vercel switch` מעבירה את Vercel CLI לצוות הזה גם בפקודות הבאות. בכל הודעה אחרת, תקן את מה שכתוב בה והרץ שוב `npm run setup`. ה-setup מקשר את הפרויקט בעצמו: אל תריץ `vercel link` ידנית.

**"הקישור לא מוביל לקובץ אודיו או וידאו."**

קבע את השיתוף של הקובץ ל"כל מי שיש לו את הקישור", ושלח קישור לקובץ עצמו, לא לתיקייה. קבצים גדולים מאוד ב-Google Drive לפעמים מחזירים דף אזהרה במקום הקובץ; הבוט מציע אז לנסות Dropbox (קישורי Dropbox עוד לא נבדקו בפועל).

**ה-doctor מדווח על "Recordings stored at Soniox"**

אם שום דבר לא מתומלל ברגע זה, אלה שאריות של מסירות שנכשלו. שלח את ההקלטות האלה שוב. Soniox מוחק את השאריות אחרי 30 יום.

**"התמלול נכשל." או "משהו השתבש."**

שלח את ההקלטה שוב. אם זה חוזר, הרץ `npm run doctor` ובדוק את הלוגים של הפונקציה בממשק של Vercel.

## פיתוח

```bash
npm run check
npm run dev
```

- הפקודה `npm run check` מריצה lint, typecheck ובדיקות יחידה, בלי רשת.
- הפקודה `npm run dev` מריצה את הבוט על המחשב הזה ב-long polling.

הפקודה `npm run dev` משתמשת ב-`.env.local`, לא צריכה tunnel, וממתינה לכל תמלול בתוך התהליך. אם לטוקן של הבוט רשום webhook (בוט שכבר עלה), היא מסרבת לרוץ, כי היא הייתה מנתקת את הבוט הזה. לפיתוח השתמש בבוט נפרד מ-@BotFather, או הרץ `npm run dev -- --takeover`, שמנתק את הבוט שעלה עד שתריץ שוב `npm run setup`. הפקודה `npm run dev` עוד לא נבדקה בפועל.

ה-CI מריץ `npm run check` על Node 22 ו-24 בכל push ל-`main` ובכל pull request. כללי הפרויקט למפתחים ולסוכני קוד נמצאים ב-[CLAUDE.md](CLAUDE.md).
